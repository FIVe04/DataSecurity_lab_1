# Лабораторная работа 1 по дисциплине "Защита данных"
#### Тема: "Разработка программы разграничения полномочий пользователей на основе парольной аутентификации"

## Требования к паролю
Пароль должен содержать:
- латинские буквы,
- символы кириллицы,
- знаки арифметических операций (`+`, `-`, `*`, `/`).

## Особенности работы программы
- При первом запуске создаётся пользователь **admin** с пустым паролем.  
  При входе необходимо пройти регистрацию и установить пароль.
- При добавлении нового пользователя администратором он также создаётся с пустым паролем, и при первом входе должен зарегистрироваться.
- Все данные (имя пользователя и пароль) хранятся в локальной базе данных.  
  Пароли сохраняются **не в открытом виде**, а в зашифрованной форме.

## Шифрование паролей
Для защиты паролей используется **комбинированное шифрование**:

1. **Шифрование перестановкой**  
   - Ключ формируется из имени пользователя.  
   - Символы пароля переставляются в каждом блоке в соответствии с ключом.  
   - Если длина пароля меньше длины ключа — он дополняется пробелами.  
   - Если длина пароля больше — текст разбивается на блоки.

2. **Шифрование гаммированием**  
   - Результат перестановки дополнительно шифруется методом гаммирования.  
   - Используется генератор последовательности по формуле:
G_{i+1} = (A * G_i + C) mod 256
где A = 5, C = 3, G0 = 1
   - Каждый байт символа складывается по модулю 2 (операция XOR) с элементом гаммы.

## Алгоритм работы
- При регистрации:  
  1. Пользователь вводит пароль.  
  2. Программа выполняет перестановку символов с ключом на основе имени пользователя.  
  3. Результат шифруется гаммированием.  
  4. Полученные байты преобразуются в hex-строку и сохраняются в БД.

- При аутентификации:  
  1. Из БД берётся зашифрованный пароль.  
  2. Он расшифровывается в обратном порядке: сначала гаммирование, затем обратная перестановка.
  3. Расшифрованный пароль сравнивается с введённым пользователем.

Таким образом, в базе данных никогда не хранятся пароли в открытом виде, что обеспечивает базовую защиту от компрометации данных.

## Шифрование базы данных пользователей

Помимо защиты паролей, сама база данных с учётными записями хранится в зашифрованном виде.  
Для этого используется симметричное шифрование по заданным параметрам лабораторной работы:

- **Тип шифрования:** блочный (AES, размер ключа 128 бит)  
- **Режим:** CFB (обратная связь по шифротексту)  
- **Ключ:** генерируется из парольной фразы администратора  
- **Алгоритм хеширования:** MD5 (для получения ключа из фразы)  
- **Добавление случайного значения:** при каждом шифровании используется случайный IV (инициализационный вектор), который сохраняется вместе с зашифрованными данными.

### Реализованные функции (`app/services/crypto.py`)

- `derive_key(password: str, salt: bytes) -> bytes`  
  Генерация ключа для AES. В качестве основы берётся парольная фраза, введённая пользователем при запуске программы, к ней добавляется соль, результат хэшируется алгоритмом **MD5**.

- `encrypt_aes_cfb(key: bytes, data: bytes) -> bytes`  
  Шифрование произвольных данных (например, содержимого базы SQLite) с помощью AES в режиме CFB. На выходе формируется `IV + ciphertext`.

- `decrypt_aes_cfb(key: bytes, enc_data: bytes) -> bytes`  
  Расшифровка данных AES в режиме CFB. Первые 16 байт — это IV, оставшиеся байты — зашифрованный текст.

- `encrypt_file(key: bytes, infile: str, outfile: str)`  
  Шифрование файла на диске (чтение → шифрование → запись).

- `decrypt_file(key: bytes, infile: str, outfile: str)`  
  Расшифровка файла на диске (чтение → расшифровка → запись).

### Работа приложения с зашифрованной БД

1. **Запуск программы**  
   - Пользователь вводит парольную фразу.  
   - Из фразы и соли генерируется ключ с помощью `derive_key()`.  
   - Программа пытается расшифровать файл `users.db.enc`.  
   - Если пароль неверный (ключ не подошёл) — приложение завершает работу.  

2. **Загрузка БД**  
   - Расшифрованные байты SQLite-базы загружаются во **временную базу в памяти** (`:memory:`).  
   - Все операции с пользователями (регистрация, аутентификация, изменение пароля) выполняются в этой базе.  
   - На диск база в открытом виде никогда не пишется.  

3. **Работа с пользователями**  
   - Аутентификация и регистрация происходят так же, как и раньше (перестановка + гаммирование пароля).  
   - Администратор может управлять пользователями через интерфейс.  

4. **Завершение программы**  
   - При закрытии приложения содержимое in-memory БД выгружается во временный файл.  
   - Этот файл шифруется функцией `encrypt_aes_cfb()` и сохраняется как `users.db.enc`.  
   - Временный файл удаляется.  

Таким образом, база данных всегда хранится в зашифрованном виде, а в оперативной памяти находится только во время работы программы.
